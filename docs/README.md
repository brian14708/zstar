# Documentation

Build from the repository root:

```sh
nix develop --command just docs
```

This installs locked dependencies and writes the site to `docs/dist`. The
Python API is generated by starlight-pydocs using locked Griffe static analysis
of `python/src`. No native extension build or installed wheel is needed. Public
exports, types, and the fsspec filesystem appear within the Starlight site at
`/zstar/api/python/`. The extraction adapter in `scripts/extract-python-api.py`
makes internal generic mixin bases resolvable for inherited API members.

Edit SDK overviews in their package READMEs and the specifications under
`spec/draft/` (core, external content, and the catalog proposal). The external-content specification includes
an informative CAS storage appendix. Their site pages are
generated. Tutorials live in `src/content/docs/tutorials`, and advanced usage
guides in `src/content/docs/guides`. All pages use `src/styles/typography.css`
for reading styles and `src/styles/theme.css` for the shared light/dark palette
and API reference styling.

Tutorials import runnable examples from each SDK's examples directory. The
`Example` component renders whole files or named regions, so excerpts stay in
sync with the programs. Missing regions fail the site build.

Preview at `http://localhost:4321/zstar/`:

```sh
nix develop --command pnpm --filter zstar-docs run preview
```

The pnpm workspace and lockfile live at the repository root. Run `pnpm install`
there to install dependencies for all workspace packages.

For live editing, run `pnpm --filter zstar-docs run dev` in the Nix shell.
Rebuild after changing SDK READMEs, the specification, or Python docstrings.
Site search includes the Python API; the API pages also have symbol search.

Set the repository's Pages source to **GitHub Actions**. The Documentation
workflow checks pull requests and deploys pushes or manual runs on `main` to
`https://brian14708.github.io/zstar/`.

The pinned starlight-pydocs patch in `patches/` gives top-level classes their
own pages, keeps the reference overview compact, and groups the class table of
contents by member kind. It also places constructor documentation on the class
and source links beside headings. When upgrading the plugin, review the patch
against its page model, HTML renderer, and Markdown output before updating the
pin.

The Python API reference follows public exports in `zstar` and `zstar.types`.
Wire tuples, CBOR extension values, and underscored helpers are private and do
not appear as standalone public types.
